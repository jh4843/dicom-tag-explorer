## 1. DICOM 적합성 범위 (leader)

표준 근거는 DICOM 2026d 판(dicom.nema.org `current`)을 2026-10-26에 확인한 것이다.

### 1.1 대상과 범위

| 항목 | 지원 범위 | 표준 근거 |
|------|-----------|-----------|
| 파일 포맷 | PS3.10 파일만 연다. 128바이트 Preamble + `DICM` 접두어 + File Meta Information(그룹 0002, 항상 Explicit VR Little Endian)을 요구한다. `DICM`이 없으면 "DICOM 아님"으로 처리한다(Q-05와 같은 판별 기준) | PS3.10 7.1 |
| SOP Class (우선) | VL Whole Slide Microscopy Image Storage (`1.2.840.10008.5.1.4.1.1.77.1.6`). WSI 분류, 피라미드 통합, 슬라이드 뷰의 대상이다 | PS3.3 A.32.8, PS3.4 B.5 |
| SOP Class (그 외) | 모든 SOP Class를 연다. Tag Tree와 RAW는 항상 표시하고, 이미지는 1.3의 디코더로 풀리는 경우만 첫 프레임을 표시한다(Q-01). Media Storage Directory Storage(`1.2.840.10008.1.3.10`)는 DICOMDIR로 다룬다 | PS3.4 B.5 |
| Image Type (WSI) | 값 3 `VOLUME`, `LABEL`, `OVERVIEW`, `THUMBNAIL`로 분류한다. 값 4 `NONE`/`RESAMPLED`는 표시만 한다. 정의되지 않은 값 3(사내 샘플 3DHISTECH의 `LOCALIZER`, `REGIONLOCALIZER`)은 "기타"로 두고 값을 그대로 표시한다. 기타는 슬라이드 뷰에 쓰지 않는다 | PS3.3 C.8.12.4.1.1 (Table C.8.12.4-2, -3) |
| Dimension Organization | `TILED_FULL`은 프레임 순서가 암묵적이다(행 → 열 → 초점면 → Optical Path). Per-Frame Plane Position이 없어도 된다. `TILED_SPARSE`(또는 값 없음)는 Per-Frame Functional Groups의 Plane Position (Slide)으로 타일 위치를 얻는다. 두 방식 모두 슬라이드 뷰를 지원하고, 위치 해석은 wsidicom이 한다 | PS3.3 C.7.6.17 (Table C.7.6.17-1), C.7.6.17.3, C.8.12.6.1 |
| 피라미드 레벨 | 같은 WSI(2.4 그룹 규칙)의 `VOLUME` Instance를 Total Pixel Matrix Columns/Rows(0048,0006/0007) 크기순으로 레벨화한다. 레벨 간 배율은 Shared Functional Groups의 Pixel Measures > Pixel Spacing 비로 계산한다. 사내 샘플은 모두 정확히 2배 간격이다 | PS3.3 C.8.12.4, C.7.6.16.2.1 |
| 초점면 | Z Offset in Slide Coordinate System(0040,074A, µm)으로 구분한다. 한 Instance에 여러 초점면(Total Pixel Matrix Focal Planes(0048,0303) > 1)이 있어도 열린다. 표시 규칙은 L-04를 따른다 | PS3.3 C.8.12.4.1.3, C.8.12.6.1 |
| Optical Path | Optical Path Sequence(0048,0105)와 Optical Path Identification(0048,0207)으로 구분한다. 슬라이드 뷰는 첫 번째 Optical Path를 쓴다(L-04). 여러 Optical Path 합성(형광 채널 합성)은 범위 밖이다 | PS3.3 C.8.12.5, C.8.12.6.2 |
| Concatenation | 같은 Series 안에서 Concatenation UID(0020,9161)로 나뉜 Instance는 각각 Instance 노드로 나열하고, 슬라이드 뷰에서는 wsidicom이 하나의 레벨로 합친다. 사내 샘플에 없어 미검증이다 | PS3.3 C.7.6.16 |
| Encapsulated Pixel Data | Basic Offset Table(빈 경우 포함), Extended Offset Table(7FE0,0001), Fragment Item, Sequence Delimitation을 Tag Tree 노드로 표시한다 | PS3.5 A.4, PS3.3 C.7.6.3 |
| Undefined Length | SQ, Item, Encapsulated Pixel Data의 `FFFFFFFFH` 길이를 지원한다. Delimitation Item까지를 요소 범위로 본다(Q-06) | PS3.5 7.1.2, 7.5.1, 7.5.2 |
| DICOMDIR | Basic Directory IOD를 읽는다. Directory Record Sequence(0004,1220)의 레코드를 Offset of the First Directory Record of the Root Directory Entity(0004,1200), Offset of the Next Directory Record(0004,1400), Offset of Referenced Lower-Level Directory Entity(0004,1420)로 계층화한다. 이 Offset은 파일 첫 바이트(Preamble 포함) 기준의 Item 시작 위치이다(사내 샘플로 확인). Referenced File ID(0004,1500)는 DICOMDIR가 있는 폴더 기준 상대 경로이다. 쓰기는 하지 않는다 | PS3.3 Annex F (F.3, F.5), PS3.10 8 |
| Private Tag | 값과 바이트를 그대로 표시한다. 이름은 pydicom 사설 사전(Private Creator 기준)에 있으면 쓰고, 없으면 `Private` 또는 Private Creator 값으로 표시한다 | PS3.5 7.8 |
| 범위 밖 | 쓰기·편집·익명화, 네트워크(DIMSE, DICOMweb), 주석(Microscopy Bulk Simple Annotations 등), 미니맵 | DIR 2장 |

### 1.3 Transfer Syntax와 디코더

Tag Tree와 RAW는 아래 모든 Transfer Syntax에서 동작한다. "이미지" 열은 v0.1.0에서 이미지를 표시하는지를 뜻한다. 디코더는 3장에서 승인된 것만 쓴다. GPL 코덱(pylibjpeg-libjpeg 등)과 imagecodecs는 쓰지 않는다(3.3).

| Transfer Syntax | UID | Tag/RAW | 이미지 | 디코더 | 근거 |
|-----------------|-----|---------|--------|--------|------|
| Implicit VR Little Endian | `1.2.840.10008.1.2` | O | O | pydicom (native) | PS3.5 A.1 |
| Explicit VR Little Endian | `1.2.840.10008.1.2.1` | O | O | pydicom (native) | PS3.5 A.2 |
| Deflated Explicit VR Little Endian | `1.2.840.10008.1.2.1.99` | O (Offset 예외, Q-06) | O | pydicom + 표준 라이브러리 zlib | PS3.5 A.5 |
| Explicit VR Big Endian (Retired) | `1.2.840.10008.1.2.2` | O | O | pydicom (native) | PS3.5 A.3 |
| JPEG Baseline (Process 1) | `1.2.840.10008.1.2.4.50` | O | O | Pillow (libjpeg-turbo). WSI 타일은 wsidicom PillowDecoder | PS3.5 A.4.1 |
| JPEG Extended (Process 2 & 4) | `1.2.840.10008.1.2.4.51` | O | 8bit만 | Pillow (pydicom pillow 플러그인) | PS3.5 A.4.1 |
| JPEG Lossless (Process 14, SV1 포함) | `1.2.840.10008.1.2.4.57`, `.70` | O | X | 없음 (pydicom은 GPL 플러그인 또는 GDCM을 요구) | PS3.5 A.4.1 |
| JPEG-LS Lossless / Near-Lossless | `1.2.840.10008.1.2.4.80`, `.81` | O | X | 없음 | PS3.5 A.4.3 |
| JPEG 2000 (Lossless Only 포함) | `1.2.840.10008.1.2.4.90`, `.91` | O | O | Pillow (OpenJPEG 2.5.4) | PS3.5 A.4.4 |
| HTJ2K 계열 | `1.2.840.10008.1.2.4.201`~`.203` | O | X | 없음 (pydicom은 pylibjpeg-openjpeg 요구. 샘플 없음) | PS3.5 A.4 |
| RLE Lossless | `1.2.840.10008.1.2.5` | O | O | pydicom (native RLE) | PS3.5 A.4.2 |
| 그 외 (MPEG, JPEG XL 등) | - | O | X | 없음 | PS3.5 |

- 이미지가 X인 경우 Image 영역은 5.3.5 "이미지 디코딩 실패" 상태로 표시한다.
- JPEG-LS나 JPEG Lossless 지원이 필요해지면 `pyjpegls`(MIT) 또는 `pylibjpeg-openjpeg`(MIT)를 license-check 후 다음 버전에서 추가한다. v0.1.0 요구사항과 사내 샘플에는 필요하지 않다.

## 2. 아키텍처 (leader)

### 2.1 원칙

- UI 스레드에서는 파일 I/O, 색인, 디코딩, 검색을 하지 않는다(5.3.4).
- DICOM 해석 로직(`core/`)은 Qt에 의존하지 않는다. pytest는 `core/`, 빌드 스크립트, 그리고 위젯 없이 확인할 수 있는 UI 데이터(토큰, 아이콘 매니페스트, 리본 배치, 번역 파일)를 대상으로 한다. 화면 동작은 수동 확인한다(pytest-qt는 도입하지 않는다).
- UI의 색, 글꼴, 크기, 아이콘은 Design System(`docs/design-system/`)의 토큰과 아이콘만 쓴다(2.8). 코드에 hex 값을 직접 쓰지 않는다.
- Tag Tree와 RAW의 근거는 **자체 바이트 색인**(2.3)이다. pydicom은 값 해석(VR, 문자셋, 사전, 픽셀 디코딩)에 쓴다. pydicom의 Dataset은 Delimiter 위치와 요소 헤더 위치를 보존하지 않기 때문이다.
- WSI 슬라이드 뷰와 VOLUME 타일 읽기는 wsidicom에 맡긴다. wsidicom 호출은 `core/wsi.py` 한 곳으로 모은다.

- 루트의 `build/`와 `dist/`는 PyInstaller 작업 폴더이므로 소스를 두지 않고 `.gitignore`에 `/build/`, `/dist/`로 넣는다. `tests/build/`가 무시되지 않도록 루트 기준으로 쓴다. `resources/i18n/*.qm`도 생성물이므로 `.gitignore`에 넣는다.

### 2.3 요소 색인 (ElementIndex, L-02)

- `indexer.py`는 File Meta(Explicit VR LE)와 본문(Transfer Syntax에 따른 Implicit/Explicit, Little/Big Endian)을 순회하며 노드를 **파일 순서(전위 순회)**로 기록한다. 노드는 Preamble, `DICM`, 데이터 요소, Item, Item Delimitation, Sequence Delimitation, Basic Offset Table, Fragment를 모두 포함한다(R-11).
- 노드마다 `start`(int64), `header_len`(int16), `total_len`(int64, Undefined Length는 Delimiter 끝까지로 확정), `parent`(int32), `subtree_end`(int32, 하위 마지막 노드 다음 번호), `tag`(uint32), `vr`(2바이트), `flags`(Undefined Length 등)를 `array`/numpy 컬럼에 둔다. 값 문자열은 저장하지 않는다.
- 역매핑(DIR-006)은 `start` 배열에서 `bisect`로 오프셋 이하의 마지막 노드를 찾은 뒤, 그 노드부터 부모 쪽으로 올라가며 `[start, start+total_len)`에 오프셋을 포함하는 첫 노드를 고른다. 전위 순회 순서이므로 이것이 가장 깊은 노드이다. 비용은 O(log n + depth)이다.
- Tag Tree 모델은 노드 번호를 `internalId`로 쓰는 지연 생성 모델이다. 자식 목록은 `parent`/`subtree_end`로 필요할 때 계산하고, 값 문자열은 화면에 보일 때 `values.py`가 mmap에서 해당 바이트만 읽어 pydicom으로 해석한 뒤 LRU 캐시에 둔다. 따라서 색인과 지연 생성 모델은 충돌하지 않는다.
- Encapsulated Pixel Data의 Fragment 노드는 파일을 열 때 만들지 않는다. Pixel Data 노드를 펼치거나 RAW 커서가 Pixel Data 범위에 들어가면 백그라운드에서 Fragment 헤더를 순회해 색인에 덧붙인다. 그 전까지 Pixel Data 범위의 바이트는 Pixel Data 노드로 매핑한다.
- 손상 파일은 순회가 실패한 위치에 `<파싱 중단: 원인>` 오류 노드를 추가하고 그 이전 노드를 유지한다(5.3.5).
- 측정치(사내 샘플, 순수 Python 프로토타입, Windows 11)는 다음과 같다.
  - S-V z_0 level_0(775 MB, 요소 121,938개)의 헤더 색인은 노드 162,569개, 133 ms, 메모리 약 4 MB였다.
  - 같은 파일의 Fragment 20,306개 추가 색인은 디스크 캐시가 비었을 때 약 6.1 s, 캐시된 뒤 178 ms였다. Fragment 색인을 지연·백그라운드로 두는 근거이다.
  - 3DHISTECH `LOCALIZER` 파일(요소 40,109개)은 노드 49,125개, 34 ms였다.
  - 비교로 pydicom `iterall()`로 레벨 0의 모든 요소를 해석하는 데 1,372 ms가 걸렸다. 검색은 값을 해석해야 하므로 백그라운드에서 한다(2.5).

### 2.4 분류 모델

- `DicomFile` 요약 메타는 색인 결과에서 필요한 요소만 해석해 만든다. SOP Class UID, Study/Series Instance UID, Image Type, Total Pixel Matrix Columns/Rows, Columns/Rows, Number of Frames, Container Identifier, Series Description, Transfer Syntax를 쓴다. 초점면 Z는 Shared Functional Groups에서, 없으면 Per-Frame Functional Groups의 **첫 Item만** 해석해 얻는다.
- WSI 그룹 키는 (Study Instance UID, Series Instance UID)이다(DIR-013). SOP Class가 WSI가 아닌 파일은 `(Non-WSI)` 그룹에 넣는다.
- 레벨 번호 `Ln`은 그룹 안 VOLUME의 서로 다른 Total Pixel Matrix 크기를 큰 순서로 매긴 순위이다. 같은 크기의 Instance(초점면, Optical Path, Concatenation)는 같은 `Ln`을 쓴다. 초점면 표기는 L-04를 따른다.
- DICOMDIR 모델은 DICOMDIR 파일마다 레코드 트리를 만들고, 각 레코드에 "DICOMDIR 안 Item의 파일 오프셋"과 IMAGE 레코드의 참조 경로를 둔다.

### 2.5 백그라운드 처리와 취소 (5.3.4 위임)

| 작업 | 실행 위치 | 취소 방식 |
|------|-----------|-----------|
| 폴더 탐색, 다중 파일 열기(색인+요약) | `QThreadPool.globalInstance()` (최대 스레드 4). 파일 1개 = `QRunnable` 1개 | 공유 `CancelToken`. 시작 전 작업은 그 열기 배치의 작업만 `QThreadPool.tryTake()`로 꺼내 버린다(전역 풀의 검색·디코딩·Fragment 작업은 건드리지 않는다. `clear()`는 쓰지 않는다). 실행 중 작업은 색인 루프가 4,096노드마다 토큰을 확인해 중단한다. 이미 끝난 파일은 유지한다 |
| 파일 1개 재파싱, DICOMDIR IMAGE 참조 파일 읽기 | 같은 풀 | 같은 토큰 방식. 취소 시 "취소됨" 상태로 남긴다 |
| Fragment 색인 | 같은 풀 | 파일 선택이 바뀌면 토큰으로 중단한다 |
| 검색 | 같은 풀. 입력 300 ms debounce 후 시작 | 새 검색이 시작되면 이전 검색 토큰을 취소한다. 결과는 세대 번호가 최신일 때만 반영한다 |
| Instance 이미지 디코딩 | 같은 풀 | 선택이 바뀌면 세대 번호로 결과를 버린다(디코딩 자체는 중단하지 않는다) |
| WSI 타일 읽기 | 전용 `QThreadPool` 1개 (최대 스레드 4) | 아래 L-03 |

- 작업 결과는 `QObject` 기반 Signals로 queued connection을 통해 UI 스레드에 전달한다.
- 워커는 `QImage`까지만 만들고 `QPixmap` 변환은 UI 스레드에서 한다(`QPixmap`은 GUI 스레드 전용이다).
- 타일 읽기(L-03)는 다음과 같이 한다.
  - 보이는 타일마다 `QRunnable`을 만든다. 각 작업은 (슬라이드, 레벨, 타일 좌표, z, Optical Path, 세대 번호)를 가진다.
  - Pan/Zoom/선택이 바뀌면 세대 번호를 올리고 `tile_pool.clear()`로 시작 전 요청을 버린 뒤 새로 보이는 타일만 다시 넣는다(타일 풀은 전용 풀이라 `clear()`를 쓴다). 실행 중인 `read_tile`은 중단할 수 없으므로 끝난 뒤 세대 번호가 다르면 결과를 버린다. 다만 실행 중인 요청의 타일이 새 화면에도 보이면 그 요청을 새 세대로 이월해 결과를 쓴다(같은 타일을 다시 요청하지 않는다). 타일 1개는 수십 ms라 이 방식으로 충분하다.
  - 타일 결과는 UI 쪽 LRU 캐시에 둔다. 상한은 장 수가 아니라 **메모리 256 MiB**이다(L-05). 항목 크기는 `QPixmap` 기준 `가로 × 세로 × 4` 바이트로 센다. 저장되지 않음·읽기 실패 표시는 0바이트로 세고, 대신 전체 항목 수를 4,096개로 제한한다. wsidicom 자체 프레임 캐시(decoded 100 MiB, encoded 100 MiB 기본값)는 그대로 쓴다.
  - 근거 계산은 다음과 같다.
    - Windows에서 `QPixmap`은 32bpp이므로 1024×1024 타일 1장은 4 MiB이다. 기존 256장 상한은 1 GiB이고, developer가 관측한 프로세스 메모리 1.15 GB와 맞는다.
    - 256 MiB는 1024² 타일 64장, 512² 타일 256장, 256² 타일 1,024장이다.
    - 레벨 자동 선택(SPEC-024)은 표시 배율이 레벨 픽셀 대비 0.5 초과 1 이하가 되게 하므로 보이는 레벨 픽셀은 뷰포트의 최대 2배이다. 이미지 영역 최대화 상태의 큰 화면(2560×1300 논리 픽셀, 4K 150%)에서 1024² 타일은 최대 (5,120/1,024 + 1) × (2,600/1,024 + 1) ≈ 6 × 4 = 24장(96 MiB)이 보인다. 64장은 최악의 한 화면보다 2.6배 크므로 되돌아가는 Pan에도 캐시가 남는다.
    - 예상 최대 메모리는 타일 캐시 256 MiB + wsidicom 캐시 200 MiB + 앱 기본(Python, Qt, 색인) 약 200 MB로 약 0.7 GB이다. TC-050은 800 MB를 상한으로 확인한다.
    - G2 실측(소스 실행, 샘플 35개를 모두 연 상태)은 L0 확대 직후 503 MB, 60초 Pan/Zoom 끝 798 MB였다. 앱 기본이 예상보다 큰 것은 35개 파일 색인과 wsidicom이 연 L0 Dataset(per-frame Item 약 2만 개 × 2파일) 때문으로 추정한다. 판정은 8.2 M-01이다.
  - 단일 레벨 타일 모드(SPEC-022, 레벨 자동 전환 없음)는 축소하면 보이는 타일이 수천 장이 될 수 있다. 타일은 화면 배율에 맞춰 2의 거듭제곱 단계로 줄여(박스 평균) 캐시한다. 줄인 타일은 화면에 그려지는 크기의 1~2배이므로, 보이는 타일 전체의 메모리가 화면 크기 수준으로 묶인다. 화면 중심에서 가까운 순으로 `캐시 용량(줄인 타일 기준, 장)의 절반`까지 읽는다. 요청 수가 캐시 용량보다 크면 보이는 타일끼리 서로 밀어내며 다시 읽기를 반복하기 때문이다. 동시 요청은 128장 이하로 묶고, 묶음이 끝나면 다음 묶음을 요청한다. 캐시 장 수 상한은 65,536장이다(레벨 0 단독 맞춤 보기 20,306장 포함).
- 동시에 열어 두는 `WsiDicom` 객체는 1개다. 다른 WSI를 선택하면 이전 객체를 닫는다. 파일 선택 중인 `DicomFile`의 mmap도 1개만 유지한다.

### 2.6 데이터 흐름

1. **열기.** `main_window`가 경로 목록을 받으면 `scan`이 폴더를 펼친다. 파일마다 열기 작업이 `indexer`로 헤더 색인을 만들고 `DicomFile` 요약을 만든다. 완료 Signal마다 `explorer_models`가 파일/WSI 탭에 노드를 추가한다. DICOMDIR이면 `dicomdir`가 레코드 트리를 만들어 DICOMDIR 탭에 추가한다.
2. **Instance 선택.** `tag_tree_model`이 해당 `ElementIndex`를 붙이고 `hex_view`가 같은 `bytesource`를 붙인다. 이미지 디코딩 작업이 시작된다. VOLUME이면서 프레임이 여러 개면 `wsi`가 그 파일 하나로 슬라이드를 열어 타일 모드로 표시하고, 그 외에는 `image_decode`가 첫 프레임을 디코딩한다.
3. **WSI 노드 선택.** `wsi`가 그룹의 파일 목록으로 `WsiDicom.open([...])`를 호출한다(Study/Series 그룹 = wsidicom 슬라이드). `image_view`가 타일 모드로 전환되고 요약표가 표시된다.
4. **Tag ↔ RAW.** Tag 선택은 노드 번호 → (start, header_len, total_len) → Hex 하이라이트로 이어진다. Hex 클릭은 오프셋 → `element_index` 역매핑 → 노드 번호 → 모델 인덱스 → 상위 펼침·선택으로 이어진다.
5. **검색.** `search`가 조건을 파싱하고 백그라운드에서 노드를 순회해 일치 노드 번호 목록을 돌려준다. 이동은 목록에서 다음/이전을 골라 4번처럼 선택한다.

### 2.7 빌드·배포 구성 (DIR-019 ~ DIR-022)

- **빌드 환경.** 저장소 루트의 `.venv`(git 무시 대상, 전역 site-packages 미포함)를 깨끗한 venv로 쓰고, 여기에 `requirements.txt`와 `requirements-dev.txt`만 설치하고 빌드한다. 개발 PC 전역에는 imagecodecs 등 대장에 없는 패키지가 설치되어 있고, wsidicom은 imagecodecs가 있으면 자동으로 import하므로 전역 환경으로 빌드하면 금지 모듈이 섞인다.
- **PyInstaller spec** (`packaging/dicom_tag_explorer.spec`). onedir를 만든다. PySide6와 shiboken6의 Python 파일은 `module_collection_mode`로 exe 안 아카이브가 아닌 `_internal` 폴더에 `.py`로 둔다(3.5). `Analysis` 직후 `scripts/gen_notices.py`의 함수를 호출해 고지 파일을 만들고 금지 검사를 한다. 결과 `THIRD_PARTY_NOTICES.txt`를 `datas`에 넣은 뒤 `PYZ`/`EXE`/`COLLECT`를 만든다. 이렇게 하면 `_internal`의 고지와 실제 번들 내용이 항상 같다.
- **고지 생성기** (`scripts/gen_notices.py`)는 다음 순서로 동작한다.
  1. `Analysis`의 `pure`(Python 모듈)와 `binaries`/`datas`(파일) 목록을 받는다.
  2. 모듈은 `importlib.metadata.packages_distributions()`로, 파일은 각 배포판 `RECORD`(`Distribution.files`)로 소유 배포판을 찾는다.
  3. 소유 배포판이 없는 파일은 Python 런타임(`sys.base_prefix`의 DLL, 표준 라이브러리 .pyd)이면 "Python 런타임" 항목으로 묶는다. 그 외는 **알 수 없는 파일로 보고 빌드를 실패**시킨다.
  4. 배포판마다 `License-Expression`, `License`, `Classifier: License ::` 메타데이터와 dist-info의 LICENSE/COPYING/NOTICE 원문을 모은다. Python 런타임은 `sys.base_prefix/LICENSE.txt`를 쓴다. PySide6/shiboken6는 wheel에 LGPL 원문이 없으므로(상용 안내 파일만 있음) `packaging/licenses/LGPL-3.0.txt`와 `GPL-3.0.txt`를 붙인다.
  5. 각 배포판을 `license_policy.toml`과 대조한다. 다음 중 하나라도 해당하면 오류 목록을 출력하고 종료 코드 1로 빌드를 실패시킨다.
     - 대장에 없는 배포판이다.
     - 대장 판정이 `금지` 또는 `보류`이다.
     - 메타데이터 라이선스 문자열이 대장에 기록된 값과 다르다(버전 변경 등으로 재확인이 필요하다).
     - 원문 LICENSE 파일을 찾지 못했다.
     - 번들된 Qt 모듈 DLL(`Qt6*.dll`)이 허용 목록(Core, Gui, Widgets, Svg와 그 플러그인) 밖에 있다. Qt Charts, Data Visualization, Virtual Keyboard 등 GPL 전용 모듈의 혼입을 막는다.
  6. 판정이 통과하면 `THIRD_PARTY_NOTICES.txt`(UTF-8)를 쓴다. 맨 앞에 목록 표(이름 | 버전 | 라이선스 | 판정)를 두고, 배포판마다 `===== {이름} {버전} ({라이선스}) =====` 머리줄과 원문을 이어 쓴다. 정보 창은 이 머리줄로 섹션을 나눈다.
- **SPDX 해석.** `OR` 식은 허용 가능한 선택지가 하나라도 있으면 그것을 고른 것으로 기록한다(PySide6의 `LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only`는 LGPL-3.0-only를 선택). `WITH` 예외는 `license_policy.toml`의 허용 예외 목록(`GCC-exception-3.1`, PyInstaller bootloader 예외)에 있을 때만 허용한다.
- **번들 준비.** `scripts/build.py`는 PyInstaller 전에 다음을 한다.
  1. `scripts/i18n.py release`로 `.ts`에서 `.qm`을 만든다. 한국어 번역에 미완료 항목이 있으면 빌드를 실패시킨다(2.8.3).
  2. `scripts/gen_tokens.py --check`로 `ui/design_tokens.py`가 `docs/design-system/tokens.json`과 같은지 확인하고, 다르면 빌드를 실패시킨다(2.8.1).
  3. 빌드 일자와 git 커밋(짧은 해시)을 `build_info.json`으로 써서 `datas`에 넣는다. 설정 창 "정보"가 읽는다. 소스 실행에서는 `dev`로 표시한다.
- **번들 데이터.** `ui/resources/icons/`(SVG 52개, `icons.json`), `ui/resources/i18n/*.qm`, Qt의 `translations/qtbase_ko.qm`만 넣는다. Qt의 다른 번역 파일은 넣지 않는다.
- **번들 제외.** 다음은 쓰지 않으므로 번들에서 뺀다. 빌드 PATH는 venv와 Windows 시스템 폴더만 남겨 다른 DLL이 섞이지 않게 한다.
  - Qt 플러그인 `generic`, `networkinformation`, `tls`, 그리고 `Qt6Network.dll`.
  - `opengl32sw.dll`(소프트웨어 OpenGL. 앱은 OpenGL을 쓰지 않는다).
  - `api-ms-win-*.dll`, `ucrtbase.dll`. Windows 10/11(DIR-017)은 UCRT를 OS에 포함한다.
  - PySide6의 도구 실행 파일(`lupdate.exe`, `lrelease.exe`, `linguist.exe`, `designer.exe` 등). 빌드 때만 쓰고 배포하지 않는다(3.2).
- **배포물 구성.** `scripts/build.py`가 onedir로 빌드하고 다음 폴더를 zip으로 묶는다. 끝나면 중간 산출물 `build/`를 지워 `dist/`에 이 폴더와 zip만 남긴다.

### 2.8 UI 기반 모듈 (DIR-023 ~ DIR-028)

기준 파일은 `docs/design-system/tokens.json`, `docs/design-system/README.md`, `docs/design-system/components/*/README.md`, `ui/resources/icons/icons.json`이다. 이 절은 그것을 Qt에서 어떻게 소비하는지만 정한다. 값과 규칙은 Design System 문서가 기준이다.

#### 2.8.1 토큰과 테마 (`design_tokens.py`, `theme.py`)

- **로딩 방식은 생성 방식이다.** `scripts/gen_tokens.py`가 `docs/design-system/tokens.json`을 읽어 `ui/design_tokens.py`를 만들고, 생성 파일을 저장소에 커밋한다. 앱은 실행 중에 JSON을 읽지 않는다.
  - 이유는 세 가지이다. 첫째, `docs/`는 배포물에 없으므로 런타임 로딩을 하려면 JSON 사본을 패키지에 하나 더 둬야 한다. 둘째, 별칭 해석 오류(없는 별칭, 순환)를 앱 실행이 아니라 생성 시점에 잡는다. 셋째, Design System README가 정한 대로 "`ui/theme.py`가 같은 이름으로 들고 있는" 형태가 된다.
  - 생성기는 팔레트(`primary-*`, `secondary-*`, `neutral-*`)와 용도 토큰의 `{이름}` 별칭을 끝까지 풀어 테마별 hex로 기록한다. 별칭이 별칭을 가리키는 경우(`caption-hover` → `{bg-400}` → `{neutral-700}`)도 푼다. 없는 이름이나 순환이 있으면 실패한다.
  - 생성 결과는 `COLORS = {"dark": {토큰: hex}, "light": {...}}`, 글꼴 패밀리와 스타일(`title`, `body`, `body-strong`, `caption`, `label`, `mono`, `mono-sm`), `space-*`, `radius-*`, `size-*`, `shadow-popup` 값이다. 파일 첫 줄에 "자동 생성, 직접 수정 금지"를 쓴다.
  - `gen_tokens.py --check`는 생성 결과와 커밋된 파일이 다르면 실패한다. 빌드(2.7)와 pytest(TC-042)가 쓴다. tokens.json이 바뀌면 개발자가 `gen_tokens.py`를 다시 실행해 커밋한다.
- **`theme.py`의 책임**은 다음과 같다.
  - 시작할 때 앱 스타일을 `Fusion`으로 정한다. `windows11`/`windowsvista` 스타일은 QPalette를 일부 무시하므로 다크 테마를 일관되게 그릴 수 없다.
  - `apply(app, name)`은 `dark` 또는 `light`를 받아 QPalette와 앱 전체 QSS를 적용한다. QPalette 매핑은 Design System README "가독성 규칙"의 Qt 적용 문단을 그대로 따른다. Fusion이 쓰는 나머지 역할은 Design System에 없으므로 Button=`bg-300`, Light·Midlight=`bg-400`, Mid·Dark=`line-strong`, Shadow=`bg-000`으로 둔다.
  - QSS는 `theme.py` 안의 템플릿 하나에 토큰 값을 넣어 만든다. 대상은 툴팁, 입력창(`bg-300`, `line-strong`, `radius-sm`, 포커스 `focus` 2px), 트리·표 헤더(`bg-300`, `label`, `ink-muted`), 항목 hover(`bg-400`), 스크롤바, 탭(선택 `accent` 2px 밑줄), Dock 제목, 상태바(`bg-100`, `caption`), 팝업 메뉴(`radius-md`), 버튼, 체크박스·라디오이다. 바탕색을 지정하는 규칙에는 짝 글자색을 함께 쓴다.
  - 다른 모듈은 `theme.color("토큰")`, `theme.hex_("토큰")`, `theme.font("스타일")`로만 값을 얻는다. 없는 토큰은 `KeyError`로 바로 실패한다. 예외는 타이틀바 닫기 hover의 흰 글리프 하나로, 용도 토큰이 없어 팔레트 `neutral-0`을 쓴다(TitleBar README의 `#ffffff`, 8.2 D-13).
  - 런타임 전환 순서는 QPalette → QSS → 아이콘 캐시 비우기(2.8.2) → `notifier().changed` 발신이다. 직접 그리는 위젯(Hex 뷰, Image 뷰 타일, delegate)은 그릴 때마다 `theme.color()`를 읽으므로 `update()`만 하면 된다. 아이콘을 가진 위젯(리본, 타이틀바, 영역 툴바, 탐색 트리)은 `changed`를 받아 아이콘을 다시 설정한다.
  - 네이티브 테두리를 쓰는 창(UI-04, UI-07, 파일 대화상자 제외)은 다크 테마에서 `DwmSetWindowAttribute(DWMWA_USE_IMMERSIVE_DARK_MODE=20)`를 켜서 제목 표시줄만 밝게 튀지 않게 한다.
- 기존 `THEMES`/`DARK_PREVIEW` 임시값과 Spec 5.3.6의 옛 hex 값은 모두 `design_tokens.py`로 대체한다. 옛 토큰 이름 `search-zero`, `border-error`, `tile-fail-*`, `tile-sparse-bg`, `image-background`, `drop-overlay-*`는 Design System 이름(`danger-bg`, `danger`, `tile-sparse`, `tile-hatch`, `bg-000` 등, 5.3.6 표)으로 바꾼다.

#### 2.8.2 아이콘 (`icons.py`)

- 이름의 기준은 `icons.json`의 `icons`이다. `icon("zoom-in")`처럼 이름으로만 가져오고, 없는 이름은 `KeyError`로 바로 실패한다.
- 원본 SVG는 다크 테마 색이다. 라이트 테마에서는 SVG 문자열의 색 값을 `recolor.light` 표대로 바꾼 뒤 렌더링한다. 비교는 대소문자를 구분하지 않는다. Qt SVG는 `currentColor`를 믿을 수 없으므로 이 방식을 쓴다(Design System README "아이콘").
- 렌더링은 `QSvgRenderer`로 16px과 32px 논리 크기를 현재 화면 배율(devicePixelRatio)에 맞춰 그려 `QIcon`에 넣는다. 100%, 150%, 200%에서 흐리지 않아야 한다.
- 캐시 키는 (이름, 테마)이다. `theme.apply()`가 `clear_cache()`를 부르고, 아이콘을 쓰는 위젯은 `theme.notifier().changed`에서 다시 가져온다. 명령 아이콘은 `ActionRegistry.refresh_icons()`가 한 번에 다시 설정한다.
- 기존 `QStyle` 표준 아이콘 임시 대응표(`_TEMP`)와 `has()`는 없앤다.

#### 2.8.3 번역 (`i18n.py`, `scripts/i18n.py`)

- **원문은 영어**이다. 코드의 `tr()` 문자열이 영어 원문이고 한국어는 번역이다(Design System "글쓰기"). Spec 5장의 한국어 문구는 한국어 번역문이다.
- **파일 위치.** `.ts`는 `src/dicom_tag_explorer/ui/resources/i18n/`에 두고 커밋한다.
  - `dicom_tag_explorer_ko.ts`는 전체 한국어 번역이다.
  - `dicom_tag_explorer_en.ts`는 `lupdate -pluralonly`로 만든 영어 복수형 전용 파일이다. `%n file(s)` 같은 원문을 영어에서 올바른 단수/복수로 보여주기 위한 것이다.
  - `.qm`은 생성물이므로 커밋하지 않는다.
- **도구.** PySide6-Essentials 6.11.0에 포함된 `pyside6-lupdate`, `pyside6-lrelease`를 쓴다(developer 확인 결과 .ts → .qm 동작). 새 의존성이 아니다(3.2).
  - `scripts/i18n.py update`는 `src/dicom_tag_explorer/` 전체에서 문자열을 추출해 두 `.ts`를 갱신한다. 사라진 문자열은 지운다(`-no-obsolete`).
  - `scripts/i18n.py release`는 `.qm`을 만든다. `dicom_tag_explorer_ko.ts`에 미완료(`unfinished`) 항목이 있으면 실패한다.
  - `.qm`은 **빌드 때 생성해 번들한다**(2.7). 소스 실행에서는 개발자가 `scripts/i18n.py release`를 한 번 실행한다. `.qm`이 없으면 경고를 로그에 남기고 영어 원문으로 실행한다.
- **런타임 전환(재시작 없음).** `i18n.apply(app, lang)`은 이전에 설치한 번역기를 모두 제거하고 새 번역기를 설치한다.
  - `ko`는 `dicom_tag_explorer_ko.qm`과 Qt의 `qtbase_ko.qm`(`QLibraryInfo.path(TranslationsPath)`, 표준 버튼·입력창 문맥 메뉴 등)을 설치한다.
  - `en`은 `dicom_tag_explorer_en.qm`(복수형)만 설치한다.
  - Qt가 모든 위젯에 `QEvent.LanguageChange`를 보낸다. 번역 문자열을 가진 위젯은 `changeEvent`에서 `retranslate()`를 호출해 텍스트, 툴팁, placeholder, 접근성 이름을 다시 설정한다.
  - 명령 텍스트는 `MainWindow`의 한 함수가 `tr()`로 만들어 레지스트리에 넘기고, `LanguageChange` 때 같은 함수를 다시 호출한다(2.8.5).
  - 모델이 보여주는 번역 문자열(탐색 트리 정보 컬럼의 `Open failed`, `File not found`, `(Non-WSI)`, 인스턴스 수 등)은 `data()`에서 만들거나, `LanguageChange` 때 `dataChanged`/`headerDataChanged`를 보낸다.
  - 이미 표시된 일시적 상태바 메시지는 다시 번역하지 않는다. Windows 기본 파일 대화상자는 OS 언어를 따른다.
- **첫 실행 기본 언어.** 저장된 값이 없으면 OS 언어와 관계없이 `en`이다(사용자 결정).
- **영어로 고정하는 용어.** Tag, VR, VM, Keyword, Transfer Syntax, SOP Class, UID, Study, Series, Instance, WSI, DICOMDIR, Item, Sequence, Fragment, Preamble, Offset, RAW, Hex와 Image Type 값(VOLUME 등), DICOMDIR 레코드 유형(PATIENT 등), Tag Tree 7컬럼 헤더(TAG, VR, VM, Length, Name, Value, Offset)이다. Image 영역 제목(`Image`), `(Non-WSI)`, 상세 검색의 `Clear`도 원문대로 둔다(리본 그룹 "이미지"는 번역한다, 8.2 D-14). 번역자는 `.ts`에서 이 용어를 바꾸지 않는다.
- PySide6의 `self.tr()`은 lupdate가 문자열이 쓰인 클래스 이름을 문맥으로 쓴다. 상위 클래스에 정의된 메서드의 `tr()`을 하위 클래스 인스턴스에서 부르면 문맥이 달라질 수 있으므로, 상속되는 코드에서는 `QCoreApplication.translate("문맥", ...)`을 쓴다. 단, 복수형(`%n`) 문자열은 lupdate가 4인자 `translate`를 인식하지 않으므로 상속되지 않는 QObject의 `self.tr()`에 둔다(현재 문맥 `WsiModel`, 8.2 D-16).

#### 2.8.4 타이틀바 (`titlebar.py`)

- 메인 창은 시각적으로 프레임이 없다. 구현은 Win32 창 스타일(`WS_CAPTION`, `WS_THICKFRAME`, `WS_MINIMIZEBOX`, `WS_MAXIMIZEBOX`, `WS_SYSMENU`)을 유지한 채 `MainWindow.nativeEvent`에서 비클라이언트 영역을 없애는 방식이다. 스타일을 유지해야 Aero Snap, 최소화 애니메이션, `Alt+Space`, `Alt+F4`가 Windows 동작 그대로 남는다. 메시지 처리는 `titlebar.py`의 함수 하나로 모으고 `MainWindow`는 위임만 한다. Qt 창에는 `FramelessWindowHint`를 주고, 창 핸들이 생긴 뒤 위 Win32 스타일을 다시 켠다(Qt가 계산하는 테두리와 실제 클라이언트 영역이 어긋나지 않게 하기 위함, 8.2 D-12).
  - `WM_NCCALCSIZE`(wParam TRUE)는 클라이언트 영역을 창 전체로 돌려준다. 최대화 상태(`IsZoomed`)에서는 클라이언트 영역을 창이 놓인 모니터의 작업 영역(`MonitorFromRect` + `GetMonitorInfo`의 `rcWork`)으로 둔다.
    - 테두리 두께를 빼는 방식은 쓰지 않는다. Qt 최대화는 프레임 없는 창을 이미 `rcWork`에 맞추므로 두께를 또 빼면 사방이 8px씩 줄어 Qt가 그린 내용의 오른쪽·아래가 잘렸다. 네이티브 최대화(Win+↑, 스냅)는 이 메시지가 Qt의 창 상태보다 먼저 와서 보정이 빠져 내용이 사방 8px 화면 밖으로 나갔다(2026-10-27 사용자 3모니터 보고, 측정으로 확인).
  - `WM_NCHITTEST`는 다음 순서로 판정한다. 최대화가 아니면 가장자리 테두리 폭 안에서 `HTLEFT`/`HTRIGHT`/`HTTOP`/`HTBOTTOM`/모서리 4개를 돌려준다. 최대화 버튼 위는 `HTMAXBUTTON`이다(Windows 11 스냅 레이아웃 표시). 타이틀바의 빈 영역은 `HTCAPTION`이다(드래그 이동, 더블클릭 최대화/복원, 우클릭 시스템 메뉴는 OS가 처리). 그 외는 `HTCLIENT`이다.
  - `HTMAXBUTTON` 영역의 클릭과 hover는 OS가 비클라이언트 메시지로 보내므로 `WM_NCMOUSEMOVE`, `WM_NCMOUSELEAVE`, `WM_NCLBUTTONDOWN`, `WM_NCLBUTTONUP`을 받아 버튼 hover 표시와 최대화/복원을 직접 한다.
  - 크기 조절 테두리 폭(최대화가 아닐 때의 `WM_NCHITTEST`)은 `GetDpiForWindow`와 `GetSystemMetricsForDpi(SM_CXSIZEFRAME) + SM_CXPADDEDBORDER`로 구한다. 모니터마다 배율이 달라도 맞아야 한다.
  - `DwmExtendFrameIntoClientArea`로 1px 여백을 줘서 창 그림자와 Windows 11 둥근 모서리를 유지한다.
  - Win32 호출은 표준 라이브러리 `ctypes`로 `user32.dll`, `dwmapi.dll`을 부른다. 새 의존성이 없다.
- 타이틀바 위젯은 높이 `size-titlebar`(32px), `bg-100`이다. 왼쪽에 앱 아이콘(Q-07)과 `DICOM Tag Explorer - {파일명}`(파일명 `ink-muted`, 넘치면 말줄임), 오른쪽에 캡션 버튼 4개를 `settings` → `window-minimize` → `window-maximize`/`window-restore` → `window-close` 순서로 둔다. 각 버튼은 46×32px, 아이콘 16px `icon-ink`이다. 상세는 TitleBar README를 따른다.
- 창 제목(`setWindowTitle`)도 같은 문자열로 설정해 작업 표시줄과 `Alt+Tab`에 보이게 한다.

#### 2.8.5 리본과 명령 레지스트리 (`actions.py`, `ribbon.py`)

- 명령은 `ActionRegistry` 하나에 이름으로 정의한다(이름, tr 텍스트, 아이콘 이름, 단축키, 체크 여부). 단축키는 창에 붙은 `QAction`이 처리하므로 리본 배치나 접힘 상태와 무관하게 동작한다. 리본, 타이틀바, 우클릭 메뉴, 단축키 목록(UI-07)은 레지스트리를 소비만 한다.
- `RIBBON_LAYOUT`은 `actions.py`에 두는 데이터이다. 구조는 `[(탭 원문, [(그룹 원문, [(명령 이름, "L" | "S"), ...]), ...]), ...]`이고 `L`은 큰 버튼, `S`는 작은 버튼이다. 탭·그룹 원문은 `QT_TRANSLATE_NOOP("Ribbon", ...)`으로 표시해 lupdate가 추출하게 한다. 배치는 5.3.3을 따른다.
- 언어가 바뀌면 `MainWindow`가 명령 텍스트를 다시 설정하고, 리본은 `LanguageChange`에서 탭·그룹 이름과 버튼 라벨을 다시 읽고 폭을 다시 계산한다. 테마가 바뀌면 `refresh_icons()`로 아이콘을 다시 설정한다.
- `ribbon.py`는 탭 줄, 그룹, 큰/작은 버튼, 폭 부족 시 축소, 접기/펼치기, 접힌 상태의 임시 펼침을 담당한다. 메뉴바(`build_menubar`)는 쓰지 않으므로 없앤다.

### 2.9 런타임 설정

- `sys.setswitchinterval(0.0005)`로 GIL 전환 간격을 0.5 ms로 줄인다. Qt 모델·paint 콜백이 워커의 순수 Python 작업 뒤에서 기다리는 시간을 줄이기 위한 것이다(developer 측정: L0 첫 렌더링 정지 1.6 s → 0.04 s).
- 로그는 `%LOCALAPPDATA%\DicomTagExplorer\logs\app.log`(UTF-8)에 남긴다. 처리되지 않은 예외와 `faulthandler`의 네이티브 크래시 스택(모든 스레드)을 기록한다. windowed exe에서 `sys.stdout`/`sys.stderr`가 없으면 이 파일로 돌린다.
- 명령줄 인자로 파일 열기는 지원하지 않는다(요구사항 없음).

### 3.5 LGPL 준수 방법 (DIR-022)

- PySide6/Qt는 동적 링크(별도 DLL)로만 사용하고 수정하지 않는다.
- 최종 산출물은 onedir이다(DIR-021). Qt DLL, PySide6·shiboken6 바인딩과 Python 파일이 `_internal` 아래 별도 파일로 있어 사용자가 수정한 버전으로 교체할 수 있다(LGPL-3.0 4(d)(1)). onefile은 실행 시 임시 폴더에 DLL을 풀어 써서 교체가 어려우므로 쓰지 않는다. LGPL-3.0·GPL-3.0 전문, Qt 소스 입수처, 교체 방법 문서를 함께 제공한다(2.7).
- EULA에서 LGPL 라이브러리 교체를 위한 수정·디버깅용 리버스 엔지니어링을 금지하지 않는다(LGPL-3.0 4항). 이 조건은 사용자에게 보고한다.

#### 5.1.2 사용자 흐름

1. **열기** (DIR-010). `Ctrl+O` 또는 파일·폴더를 창에 드래그 앤 드롭한다. 여러 파일을 한 번에 선택할 수 있다. 이미 열린 파일은 다시 추가하지 않고 기존 노드를 선택한다.
2. **분류** (DIR-012~014). 읽기가 끝난 파일부터 좌측 Pane 3개 탭에 순차로 추가된다. 진행률과 취소는 상태바에 표시한다. 열기 직후 활성 탭은 "WSI"이다. WSI 파일이 없으면 "파일" 탭을 활성화한다.
3. **선택** (DIR-015, DIR-016). 좌측 트리에서 노드를 선택한다.
   - Instance(파일) 노드를 선택하면 Tag Tree, RAW, Image에 해당 파일을 표시한다.
   - WSI 이미지 노드를 선택하면 Image에 피라미드 통합 슬라이드 뷰를 표시한다. Tag 영역에는 WSI 요약표, RAW에는 안내를 표시한다. (5.3.5 참조)
4. **확인** (DIR-005, DIR-006). Tag Tree에서 행을 선택하면 RAW가 해당 바이트를 하이라이트하고 그 위치로 스크롤한다. 반대로 RAW에서 바이트를 클릭하면 그 바이트를 포함하는 가장 깊은 노드가 Tree에서 선택되고, 상위 노드가 자동으로 펼쳐진다.
5. **검색** (DIR-008, DIR-009). `Ctrl+F`로 통합 검색에 입력하고 `Enter`/`F3`로 다음 일치 항목, `Shift+Enter`/`Shift+F3`로 이전 일치 항목으로 이동한다. 이동할 때마다 Tree 선택이 바뀌므로 RAW 하이라이트도 함께 따라간다. 컬럼을 지정하려면 `상세` 버튼으로 UI-03을 연다.
6. **설정** (DIR-023~025, DIR-027). 타이틀바 `settings` 버튼이나 `Ctrl+,`로 UI-06을 열어 언어와 테마를 바꾼다. 바꾸는 즉시 열린 화면 전체에 적용된다.

탭을 전환해도 우측 View는 바뀌지 않는다. 새 탭에 현재 표시 중인 Instance가 있으면 그 노드를 선택 상태로 맞춘다.

#### 5.1.3 Q-02 결정. 검색 결과 표시 방식

**권장안은 "전체 유지 + 하이라이트 + 다음/이전 이동"이다.** 필터 방식은 채택하지 않는다.

- Sequence/Item 계층이 유지된다. 필터 방식에서는 일치 행의 상위 노드를 별도로 남겨야 하고, 같은 Keyword가 여러 Item에 있을 때 어느 Item 소속인지 구분하기 어렵다.
- 일치 항목 주변의 Tag(같은 Item의 다른 요소, 인접 Offset)를 함께 보는 것이 Tag 확인 업무의 일반적 패턴이다.
- 이동할 때마다 Tree 선택이 바뀌므로 RAW 하이라이트(DIR-005)와 자연스럽게 연동되고, 별도 결과 목록 UI가 필요 없다.

동작 규칙은 다음과 같다.
- 검색 대상은 현재 표시 중인 파일의 모든 노드이며, 접힌 노드도 포함한다. 일치 항목으로 이동하면 상위 노드를 자동으로 펼친다.
- 입력 후 300 ms debounce로 자동 검색한다. 결과 수는 `현재/전체` 형식(예: `3 / 17`)으로 표시하고, 0건이면 입력창 배경을 오류색으로 바꾼다.
- 일치한 행은 `search-match` 배경으로 표시한다. 현재 위치는 별도 색 없이 **선택 행**(`selection`)으로 나타낸다. 이동하면 해당 행이 선택되므로 선택색과 `현재/전체` 표시로 충분하다. (5.3.6)

- Tag 영역은 Tag Tree 대신 **WSI 요약표**를 표시한다. 행 더블클릭 또는 `Enter`는 좌측 트리에서 해당 Instance를 선택한다.

- 검색 바는 비활성화한다. 요약표는 검색 대상이 아니다.

#### 5.2.3 상세 검색 패널 (UI-03, DIR-009)

`상세` 버튼을 누르면 검색 바 바로 아래에 펼쳐지고, Tag Tree는 그만큼 아래로 밀린다. 다시 누르거나 `Esc`를 누르면 접힌다.

```
                         [ Search all columns...          ][<][>]  3 / 17  [Adv ^]
+------------------------------------------------------------------------------------+
| TAG    [ 0010,0010        ]   VR     [ PN       v]   VM     [      ]                |
| Name   [ Patient          ]   Length [          ]   Offset [ 0x            ]       |
| Value  [                                                                    ]      |
| [ ] Match case   [ ] Regex                                   [Clear]               |
+------------------------------------------------------------------------------------+
```

- 통합 검색 입력은 "모든 컬럼" 조건이다. 비어 있지 않은 모든 조건을 **AND**로 결합한다. (Q-03 가정)
- 입력 규칙은 다음과 같다.
  - TAG는 `0010,0010`, `00100010`, `(0010,0010)`을 같은 값으로 취급하고 앞부분 일치(`0010`)를 허용한다.
  - VR은 편집 가능한 콤보이며 표준 VR 목록을 제공하고 완전 일치로 비교한다.
  - VM과 Length는 숫자 완전 일치로 비교한다.
  - Offset은 hex로 입력하며, 해당 바이트를 포함하는 요소가 일치한다.
  - Name과 Value는 부분 일치로 비교한다.
- 형식이 잘못된 필드는 테두리를 오류색으로 표시하고 툴팁으로 형식을 안내한다. 이 필드는 검색에서 제외한다.
- `Clear`는 상세 필드만 비우고 통합 검색 입력은 유지한다.
- 대소문자 구분과 정규식 옵션은 통합 검색 입력, Name, Value에만 적용한다. Value는 화면의 256자 절단값이 아니라 전체 값과 비교한다.
- 패널을 접으면 입력한 상세 조건은 지우지 않지만 검색에서 빠진다. 다시 펼치면 다시 적용한다. 보이지 않는 조건이 결과를 좁혀 사용자를 헷갈리게 하지 않기 위해서이다.

#### 5.2.4 좌측 Pane 분류 트리 예시 (DIR-012~014)

모든 탭은 2컬럼(`이름 | 정보`)이고 헤더는 숨긴다. 정보 컬럼은 보조 텍스트색으로 표시한다.

**파일 탭** (DIR-012). 폴더 > 파일 구조이며, 열기 요청 순서(선택·드롭 순서, 폴더는 탐색 순서)대로 정렬한다. 읽기가 끝난 순서와 무관하다.
```
v E:\Data\Slide01\
    slide01_L0.dcm          VOLUME  98304x65536
    slide01_label.dcm       LABEL
    DICOMDIR                Media Storage Directory
  ! broken.dcm              Open failed
v E:\Data\CT\
    CT0001.dcm              CT Image Storage
```

**WSI 탭** (DIR-013). Study Instance UID와 Series Instance UID가 같은 Instance를 WSI 노드 하나로 묶는다.
```
v SLIDE-001                 6 instances
    VOLUME   L0             98304x65536
    VOLUME   L1             24576x16384
    VOLUME   L2              6144x4096
    LABEL                     800x600
    OVERVIEW                 1200x400
    THUMBNAIL                 512x340
> SLIDE-002                 4 instances
v (Non-WSI)                 1 file
    CT0001.dcm              CT Image Storage
```
- WSI 노드 이름은 Container Identifier(0040,0512)를 우선 사용한다. 없으면 Series Description, 그것도 없으면 Series Instance UID의 끝 12자리를 쓴다. 툴팁에는 Study/Series UID 전체를 표시한다.
- 하위 정렬 순서는 VOLUME(큰 해상도 → 작은 해상도), LABEL, OVERVIEW, THUMBNAIL, 기타(정의되지 않은 Image Type 값 3. 값을 그대로 표시)이다. 레벨 번호 `Ln`은 VOLUME의 서로 다른 해상도 순위이며 같은 해상도의 Instance는 같은 `Ln`을 쓴다. (L-04)
- WSI에 초점면이 2개 이상이면 VOLUME 이름에 `z{k}`를 붙인다(예: `VOLUME   L0 z1`). `k`는 Z Offset 오름차순(유리 → 커버슬립) 0부터의 순번이고, 툴팁에 Z 값(µm)을 표시한다. Optical Path가 2개 이상이면 `OP {Optical Path Identifier}`를 붙인다. 같은 레벨 안에서는 z, Optical Path 순으로 정렬한다. WSI 요약표의 Level 열도 같은 표기를 쓴다. (L-04)
- Instance 노드 툴팁에는 파일 경로를 표시한다.
- 열기 실패·취소 파일은 그룹 키가 없으므로 WSI 탭에 넣지 않는다. 상태는 파일 탭에서 본다.

**DICOMDIR 탭** (DIR-014). 열린 DICOMDIR 파일마다 루트 노드 하나를 만든다.
```
v DICOMDIR                  E:\Data\Disk1\
  v PATIENT  HONG^GILDONG   ID 12345
    v STUDY  2026-10-20     Slide study
      v SERIES  SM  #1
          IMAGE  slide01_L0.dcm      VOLUME
          IMAGE  slide01_label.dcm   LABEL
        ! IMAGE  missing.dcm         File not found
```
- 루트를 선택하면 DICOMDIR 파일 자체의 Tag/RAW를 표시한다.
- PATIENT/STUDY/SERIES 레코드를 선택하면 DICOMDIR 파일을 표시하고, Directory Record Sequence(0004,1220) 안의 해당 Item을 Tree에서 선택한다.
- IMAGE 레코드를 선택하면 참조된 파일을 이 시점에 읽어 표시한다. 읽은 파일은 파일 탭과 WSI 탭에도 추가된다.

**Tag Tree 표시 규칙** (DIR-002, 003)

| 컬럼 | 형식 | 예 |
|------|------|----|
| TAG | `(gggg,eeee)` 대문자 hex | `(0028,0010)` |
| VR | 2자. Item/Delimiter는 빈칸 | `US` |
| VM | 10진수 | `1` |
| Length | 10진수, 우측 정렬. Undefined Length는 `Undef.` 표시, 툴팁에 `0xFFFFFFFF` | `512` |
| Name | DICOM Keyword. 사전에 없는 Private Tag는 `Private` 또는 Private Creator 값 | `Rows` |
| Value | 최대 256자까지 표시하고 넘으면 `…`. 전체 값은 툴팁과 복사로 확인. 바이너리 VR(OB/OW/UN 등)은 앞 16바이트 hex. Pixel Data는 `<Encapsulated N frames>` 또는 `<Native N bytes>` | `1.2.840.10008...` |
| Offset | 요소 시작(Tag 첫 바이트)의 파일 기준 위치. 8자리 대문자 hex. 4 GiB를 넘는 파일은 10자리(L-01). Deflate 파일 본문은 `-`(Q-06) | `000004A2` |

- File Meta(그룹 0002) 요소는 묶음 노드 없이 Preamble·`DICM` 다음 최상위에 파일 순서대로 둔다.
- Sequence 아래 Item은 `Item #n`(1부터)으로 표시한다. Item Delimitation과 Sequence Delimitation도 노드로 표시하고 기울임체 + `ink-muted`를 쓴다. Item, Delimiter, Basic Offset Table, Fragment의 이름은 TAG 컬럼에 쓴다. 이렇게 해야 RAW의 모든 바이트가 어떤 노드에 대응한다. (DIR-006)
- File Preamble(128바이트)과 `DICM` 접두어는 의사(pseudo) 노드로 최상단에 두고 기울임체로 표시한다.
- Encapsulated Pixel Data는 하위에 Basic Offset Table과 Fragment Item 노드를 둔다. 펼칠 때 생성한다.
- 우클릭 메뉴는 TAG 복사, Value 복사(전체 값), 행 복사(탭 구분), 하위 모두 펼치기, 모두 접기로 구성한다. 복사 명령은 레지스트리 명령이고 리본 편집 탭에도 있다. Value 복사는 `edit.copy`(Tree 포커스의 `Ctrl+C`)와 같은 동작을 "Value 복사" 라벨로 보여주는 메뉴 전용 항목이다(8.2 D-15).
- 표시 스타일(행 22px, `mono`/`ui` 컬럼, 교대 행 색 없음, 선택 행 `ink`, 말줄임)은 TagTree README를 따른다.

**RAW Hex 뷰 규칙** (DIR-004~006)

```
00000080  44 49 43 4D 02 00 00 00  55 4C 04 00 C4 00 00 00  |DICM....UL......|
```
- Hex 위에 **정보 줄** 1개(`QLabel`, 고정폭 폰트)를 둔다. 선택 요소가 있으면 `(0040,0555) AcquisitionContextSequence │ 0x00000A10–0x00000B1F │ 헤더 12 + 값 260 = 272 bytes` 형식으로 표시한다. Undefined Length 요소는 Delimiter까지 포함한 실제 범위로 계산한다. 선택이 없으면 `파일 크기 1,234,567 bytes`를 표시한다.
- 한 줄은 `Offset(8자리 hex, 4 GiB 초과 파일은 10자리)` + 공백 2칸 + 16바이트(8바이트마다 공백 1칸 추가) + 공백 2칸 + `|ASCII|`로 구성한다. 0x20~0x7E 범위 밖의 바이트는 `.`으로 표시한다.
- Tag 선택 시 하이라이트는 두 색으로 구분한다(5.3.6). 헤더(Tag+VR+Length)에는 헤더색, Value에는 Value색을 칠한다. SQ/Item을 선택하면 하위 전체 범위를 Value색으로 칠한다.
- 스크롤은 요소의 헤더 첫 줄이 뷰 위에서 2번째 줄에 오도록 맞춘다. 이미 화면에 보이면 스크롤하지 않는다.
- 바이트를 클릭하면 Hex 영역과 ASCII 영역 모두에서 그 바이트를 포함하는 가장 깊은 노드를 Tree에서 선택한다. 클릭한 바이트에는 1px 테두리 커서를 그린다.
- 키보드로 커서를 옮길 수 있다. `←`/`→`는 1바이트, `↑`/`↓`는 16바이트(1줄), `PgUp`/`PgDn`은 1화면, `Home`/`End`는 줄의 처음과 끝, `Ctrl+Home`/`Ctrl+End`는 파일의 처음과 끝으로 이동한다. `Shift`와 함께 누르면 범위를 선택한다. 커서가 옮겨지면 클릭과 같이 해당 노드를 Tree에서 선택한다(DIR-006).
- `Ctrl+G`를 누르면 Offset 이동 입력창(`QInputDialog`, hex 입력, `0x` 생략 가능)이 열린다. 파일 범위를 벗어나는 값은 입력창에 오류를 표시하고 이동하지 않는다.
- 상태바 메시지에 커서 위치를 `Offset 0x00000A24 (2596)` 형식으로 표시한다.
- 드래그로 범위를 선택한 뒤 `Ctrl+C`를 누르면 선택 범위를 hex 문자열로 복사한다.

**Image 뷰 규칙** (DIR-007, 016)

- Pan은 왼쪽 버튼 드래그로 한다(`ScrollHandDrag`).
- Zoom은 휠로 하며 커서 위치를 기준으로 한 단계 1.25배씩 바꾼다. 범위는 1% ~ 1600%이고 툴바의 `+`/`-`, `맞춤`, `1:1`도 쓸 수 있다. 맞춤 배율이 1%보다 작으면(예: S-V 레벨 0 단독 표시 약 0.6%) 최소 배율은 맞춤 배율이다.
- Rotate는 툴바의 좌회전/우회전 버튼으로 90° 단위로 돌린다(Q-04 가정). 회전 중심은 뷰 중앙이다.
- 다른 Instance나 WSI를 선택하면 보기 상태를 `맞춤`, 회전 0°로 초기화한다.
- WSI 슬라이드 뷰에서는 현재 배율에 가장 가까운 해상도 이상의 VOLUME 레벨을 자동 선택한다. 보이는 영역의 타일만 백그라운드에서 읽는다. 읽는 중, 저장되지 않음(TILED_SPARSE), 읽기 실패 타일은 서로 다르게 그린다(5.3.6). 현재 레벨과 배율은 툴바와 상태바에 `L2 / 25%` 형식으로 표시한다. 초점면이나 Optical Path가 여러 개면 가장 작은 Z Offset의 초점면과 Optical Path Sequence 첫 항목을 쓰고 `L2 z0 / 25%`처럼 표시한다. 다른 초점면은 트리에서 해당 VOLUME Instance를 선택해 본다. (L-04)
- VOLUME Instance를 단독으로 선택하면 그 레벨 하나만 같은 타일 방식으로 표시한다. 레벨 자동 전환은 하지 않는다.

#### 5.3.6 스타일 가이드

스타일의 기준은 Design System(`docs/design-system/README.md`, `tokens.json`, `components/*/README.md`)이다. 이 절은 화면 요소와 토큰의 대응만 정한다. 값(hex, px)은 여기에 쓰지 않는다.

- **테마.** 다크가 기본이고 라이트는 보조다. 설정 창에서 즉시 전환한다(SPEC-035). Qt 스타일은 `Fusion`이고 QPalette와 QSS는 토큰으로 만든다(2.8.1).
- **QPalette 매핑.** Design System README "가독성 규칙"의 Qt 적용 문단대로 Active·Inactive 두 그룹에 Window=`bg-100`, Base=`bg-200`, AlternateBase=`bg-300`, Text·WindowText·ButtonText=`ink`, PlaceholderText=`ink-faint`, Highlight=`selection`(Inactive는 `selection-inactive`), HighlightedText=`ink`, Link=`accent`, ToolTipBase=`bg-300`, ToolTipText=`ink`를 넣고, Disabled 그룹의 Text는 `ink-faint`이다. 그 밖의 역할은 2.8.1을 따른다.
- **가독성 규칙.** 바탕을 칠하면 같은 규칙에서 글자색도 정한다. 허용 조합은 Design System README의 표뿐이다. 선택 행(`selection`, `selection-inactive`) 위의 글자는 Offset의 `ink-muted`, 의사 노드, 오류색을 포함해 항상 `ink`이다. 시스템 강조색(Windows accent)은 쓰지 않는다. ForegroundRole로 색을 정한 셀은 delegate가 `State_Selected`일 때 HighlightedText로 덮어쓴다.
- **고DPI.** Qt 6 기본값(Per-Monitor DPI, `PassThrough` 반올림)을 따른다. 크기 값(px)은 100% 배율 기준 논리 픽셀이다. 아이콘은 SVG를 화면 배율에 맞춰 렌더링한다(2.8.2).
- **글꼴.** `ui`(Segoe UI Variable Text, 한국어는 맑은 고딕 폴백)와 `mono`(Consolas) 두 패밀리, 스타일 `title`, `body`, `body-strong`, `caption`, `label`, `mono`, `mono-sm`만 쓴다. Tag Tree의 TAG, VR, VM, Length, Offset 컬럼과 Hex 뷰 전체는 `mono`, Name·Value와 나머지 UI는 `body`이다. 글꼴 파일은 번들하지 않는다.
- **간격과 크기.** 간격은 `space-1`~`space-8`, 모서리는 패널 `radius-0`, 컨트롤 `radius-sm`, 팝업 `radius-md`이다. 행 높이는 `size-row`(22px)이고 교대 행 배경은 쓰지 않는다. 그림자는 떠 있는 팝업(`shadow-popup`)에만 쓴다.
- **아이콘.** `icons.json`의 52개 이름만 쓴다. 다크 원본 SVG를 라이트에서 `recolor.light`로 바꾼다(2.8.2). 상태 아이콘(`error`, `warning`, `cancelled`)은 색과 함께 항상 표시한다.

#### 5.3.8 leader 확인 요청 (구현 가능성)

- 4 GiB를 넘는 WSI 파일은 8자리 hex Offset으로 표현할 수 없다. 이런 파일에서는 Offset을 10자리로 자동 확장하는 것을 제안한다. Hex 뷰는 파일 전체를 메모리에 올리지 않고 mmap 등으로 보이는 범위만 읽는 것을 전제로 한다.
  - **결론 (L-01).** 제안대로 한다. 파일 크기가 `0xFFFFFFFF`를 넘으면 그 파일 전체에서 10자리로 표시한다. Hex는 읽기 전용 mmap으로 보이는 범위만 읽는다. 사내 샘플 최대는 775,241,552 B라 4 GiB 초과 사례는 없다.
- 바이트 → 노드 역매핑(DIR-006)을 하려면 모든 요소의 (시작, 헤더 길이, 전체 길이) 색인이 필요하다. TILED_SPARSE의 Per-Frame Functional Groups처럼 Item이 수만 개인 경우, 지연 생성 모델과 이 색인을 함께 쓸 수 있는지 확인이 필요하다.
  - **결론 (L-02).** 함께 쓸 수 있다. 색인은 컬럼형 배열이고, 모델은 노드 번호만 참조하며 값 문자열은 보일 때 해석한다(2.3). 레벨 0(Per-Frame Item 20,306개)의 헤더 색인은 노드 162,569개, 133 ms, 약 4 MB였다. Fragment는 펼칠 때 백그라운드로 색인한다.
- 슬라이드 뷰의 타일 단위 백그라운드 읽기와 요청 취소를 wsidicom으로 구현할 수 있는지 확인이 필요하다.
  - **결론 (L-03).** 가능하다. `WsiDicom.read_tile(level, (x, y), z, path)`는 파일별 잠금으로 스레드 안전하다. 진행 중인 호출은 중단할 수 없으므로 시작 전 요청은 버리고 늦게 끝난 결과는 세대 번호로 버린다(2.5). 1024×1024 타일 1장은 23~43 ms였고, 64장은 순차 322~399 ms, 4스레드 122~142 ms였다.
- 같은 해상도의 VOLUME이 여러 개인 경우(초점면, Optical Path), 슬라이드 뷰에서 어느 것을 쓸지 결정이 필요하다. UI 가정은 첫 번째 Instance를 쓰고 트리에는 모두 나열하는 것이다. **사내 샘플 S-V가 초점면 2개(z_0, z_1) × 레벨 0~8 구성이라 실제로 발생한다.** WSI 트리에서 초점면을 어떻게 구분해 나열할지(예: `VOLUME L0 z0`)도 함께 정한다.
  - **결론 (L-04).** 슬라이드 뷰는 가장 작은 Z Offset의 초점면과 첫 번째 Optical Path를 쓴다. "첫 번째 Instance"는 파일 순서나 Instance Number(샘플에서 z_0과 z_1이 0~8로 겹친다)에 따라 달라지므로 쓰지 않는다. 트리 표기는 `VOLUME   L0 z1` 형식이다(5.2.4). 슬라이드 뷰 안에서 초점면을 바꾸는 UI는 v0.1.0 범위 밖이다.
